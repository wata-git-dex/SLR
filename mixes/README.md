# SLR Mixes

Mix recipes, participants and per-person results live in dedicated `slr_mix_*` tables in SLR's existing D1 binding. No mix operation writes a Notion Session, strain or batch. Batch identities are validated against current Notion records on creation and snapshotted with brand and category. Results and notes belong to individual authenticated participants; an invitation alone creates no score, completion or XP.

The existing achievements engine adds +10 activity XP for each confirmed personal mix result. First Blend (+25), Mix Notes at five (+35) and Shared Bench after two actual participant results (+25) join the same Collection, Checklist, History, total XP and level curve. Session-based badges, normal strain averages, effects and brand/type preferences remain based on ordinary Sessions. Community mix scores average only recorded mix stars, with one result per participant. My Mixes leaves a pending participant's score blank.

Apply `push/migrations/0002-mixes.sql` before deploying the new Worker, then publish the frontend. The migration adds tables/indexes only. Preserve all existing bindings, secrets, delivery settings, schema and records. Backend-first is compatible with the prior frontend. Roll back frontend/Worker code together if necessary and retain the additive mix/history tables; never reset or drop saved records.

`POST /experiments/{list,get,create,result,try}` requires the canonical app Origin and a freshly validated invite. Subjects come from the existing host invite adapter. Clients never select an author, recipient subject or XP amount. Creation is one D1 transaction; deterministic identity/operation IDs and content hashes recover a lost response without duplicate results or awards. A participating Rat may add their result once. Try This Mix allows any freshly authenticated active Rat to enroll only themselves on an existing recipe and save their own result in one transaction. Opening or drafting a mix creates no enrollment, result or XP. The immutable recipe and other members’ results stay unchanged. Other people's results cannot be edited. Unknown experiment routes and unknown legacy save kinds cannot fall through to normal Session creation.

The journal is bounded to 25 records per page, using a stable created/id cursor. Private profile metadata is bounded to 50 recent unlocks. New recipes/notes are loaded only on Mixes navigation; no additional startup provider request or polling timer is added. The existing root data response carries only aggregate mix progress and the current member's recent reward history. Root summary revisions prevent an older read from replacing newer confirmed mix XP. Same-identity journal reads coalesce and have a 30-second cache; successful saves invalidate prior reads and cache. Account changes discard late responses.

Creation uses a fresh invite read plus two independent Notion catalog reads. List/get/result/try use a fresh invite read and D1. Result rows, history, event IDs and device fanout are deduplicated. Award history/events/delivery entries are batched atomically and bounded to ten award recoveries per save; optional delivery failure does not undo a committed recipe/result. Initial normal Session history is a silent baseline; only confirmed future Session unlocks enter History.

Drafts use a versioned identity/code-fingerprint namespace in device storage, with a stable save ID retained before sending. They contain no invite code. Cancel retains the draft; Discard Draft explicitly removes that draft. Account switches preserve the old account's draft but never expose it to the new identity. Storage, network and authorization failures retain visible recovery paths. Writes participate in the existing in-flight update guard. No service worker cache or native shell is introduced.

Validation: `node --test *.test.mjs push/test/*.test.mjs mixes/*.test.mjs`; build Worker with `pnpm --dir push build`. Browser tests use an isolated Miniflare/D1 instance with a synthetic Notion service. Production does not contain demonstration mixes or synthetic results.

Mixes uses a local catalog search with category-colored names and neutral brand/THC metadata. The dialog closes after choosing a batch; search makes no provider requests. Mix Log cards use two-column ingredient tiles and expand personal details inline. Every nonzero effect remains visible. Profile progress stays in My Lab.

v2.7.1 uses the existing type-specific leaf SVGs on compact ingredient tiles, equal-share left-to-right stripe stops, and Strain × Strain automatic names. Custom names remain limited to80 characters; automatic names retain all components. Drafts record auto/custom intent and keep the stable operation ID. Existing automatic plus-separated names display with crosses without rewriting stored records; explicit custom names are retained. The shared presentation module is versioned with the feature assets. Quick/full guides and the one-time Lab Notice cover search, naming, self-try, separate ratings and overall XP.


v2.7.2 adds International Incident, Independent Replication, Twin Suns, Double Night Shift and Opposing Forces. Each uses ranks at1/5/10/25 qualifying distinct batch combinations, then every25, at25XP per rank. Only a confirmed personal result qualifies. Two-type badges require exactly two different strain IDs and pure types; Hybrid leanings remain Hybrid. Countries are snapshotted from the freshly validated server catalog into new recipes, using the five purchase-country choices already supported by SLR. Older snapshots without countries remain unknown; no origin inference or production backfill occurs. Country and specialty counts deduplicate sorted batch IDs across duplicate recipe records and ingredient order. Ordinary completed-mix activity XP retains its existing record-based counting.

Progress aggregates in one D1 JSON/SQL query; no per-recipe Notion reads or client-side country inference. Mix history/events are per-rank, atomic and idempotent, with at most ten award recoveries per save. A failed optional award batch cannot undo a committed result; the stable save retry recovers its history. Normal Session reconciliation excludes mix ranks so their histories/notifications have one producer. The same definition/rank helpers drive overall XP, Collection, Checklist, History details and popups. Existing type badge thresholds remain unchanged. No schema migration is required.

The preview also gives Hybrid/Indica clearer separated leaflets in mix tiles while retaining the approved Sativa leaf; Energized explicitly requests emoji presentation. Main strain leaf artwork and normal ratings stay unchanged. The app, service worker and feature assets share release version2.7.2.
